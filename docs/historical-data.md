## Reconstruction assessment

Historical borough polygons plus supported sector assignments could provide a reproducible reconstruction, but modern districts cannot be substituted without proving correspondence. A sector assignment table alone supplies no coordinates. Required inputs remain dated borough boundaries or sufficiently detailed historical map sheets, authoritative assignment evidence, and documented treatment of exchanges and enclaves at the snapshot date.

Histomap is a promising route to inspect already georeferenced sheets rather than inventing control points. Before tracing, establish the sheets' survey/publication dates, whether boundaries shown are administrative or occupation boundaries, completeness across Berlin and enclaves, and permission to redistribute derived vectors. Compare seams between sheets and independently check boundary features. No georeferencing, tracing, reprojection, or geometry repair has been performed in this investigation; no positional accuracy is claimed.

## Release gate and expected artifacts

1. Archive the source version, retrieval URL, source checksum, license text/link, attribution requirements, and historical-date evidence.
2. Record supported borough-to-sector assignments and dated exceptions. Resolve Staaken/Gatow and enclaves explicitly; do not assume a single 1945–1990 geometry.
3. Record any source CRS, georeferencing control points, transformation parameters, residual errors, digitization method, scale, and uncertainty. Transform to RFC 7946 WGS84 longitude/latitude only with a reproducible process.
4. Produce `data/processed/berlin-sectors.geojson` with valid nonempty Polygon/MultiPolygon features for all four codes and attribution. Preserve disconnected parts and holes. Keep provisional geometry outside the production import path and clearly label it unverified.
5. Compare sector unions with an independently supported snapshot boundary to find gaps and excess coverage; check interior overlaps and shared seams. The existing importer checks validity and overlap, but does not prove coverage completeness or historical accuracy.
6. Only after historical/license review, create the matching SHA-256 provenance manifest. Copy the accepted release to the existing `public/data/berlin-sectors.geojson` and provenance paths used by Compose, retaining the processed source artifact. Import twice and check stable IDs, row counts, geometry, and attribution.
7. Cite evidence for test locations well inside each sector, outside coverage, and on reviewed boundaries. Run backend and browser acceptance checks. Shared-edge alphabetical API tie-breaking remains a software convention.

The empty production placeholder remains intentional. Synthetic unit-square fixtures exercise topology, shared boundaries, holes, multipart geometry, idempotency, and transactions only in the dedicated test database; they establish no historical classification. Phase 1.2 remains incomplete until verified geometry and the dependent overlay checks are available.
